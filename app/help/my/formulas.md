Assembly component များသည် ပမာဏကို ပုံသေနည်းမှ ရသည်။ ပုံသေနည်းသည် item ၏ တိုင်းထားသော တန်ဖိုးများပေါ်ရှိ အသေးစား သင်္ချာ expression တစ်ခု ဖြစ်သည်။ ဥပမာများအတွက် [Assemblies and formulas](topic:assemblies) ကို ကြည့်ပါ။

## Variables

| Item အမျိုးအစား | Variable | အဓိပ္ပာယ် |
|---|---|---|
| Linear | `L` | စုစုပေါင်း အရှည် |
| Linear | `H` | Item ၏ အမြင့် |
| Linear | `A` | နံရံဧရိယာ၊ L × H၊ ထိုအပိုင်းများ ပါသော openings များကို နုတ်ထား (BimCraft မှ takeoff)။ ထို takeoff တွင် တိုင်းတာနည်း ဖော်ပြထားလျှင် `A` ကို ထို နည်းဖြင့် တိုင်းသည်: ထို နည်း၏ အငယ်ဆုံး အရွယ်အစားထက် မကြီးသော openings များကို ထားခဲ့ပြီး နံရံများ ဆုံသည့်နေရာတွင် ထိုနည်းက ဖြတ်ထားသည်ကို ချန်ထားသည်။ Item အောက်ရှိ note တွင် နည်းကို အမည်ဖြင့် ဖော်ပြသည် |
| Linear | `N` | Run အရေအတွက် |
| Area | `A` | စုစုပေါင်း net ဧရိယာ (အပြင်ပိုင်းနှုတ် cut-outs) |
| Area | `P` | စုစုပေါင်း perimeter၊ cut-out အစွန်းများ ပါဝင်သည် |
| Area | `H` | Item ၏ အနက် သို့မဟုတ် အထူ |
| Area | `N` | ဧရိယာ အရေအတွက် |
| Count | `N` | အရေအတွက် |

- Variables များသည် item ၏ unit ဖြင့် ဖြစ်သည်: [ယူနစ်များ](topic:units) ကို ကြည့်ပါ။
- အကြီး အသေး အက္ခရာ တူသည်: `l` သည် `L` ဖြစ်သည်။
- Item ၏ ကိုယ်ပိုင် အမျိုးအစား၏ variables များသာ အလုပ်လုပ်သည်။ Linear item ပေါ် `P` သည် `"P" ဤနေရာတွင် တိုင်းတာထားသော တန်ဖိုး မဟုတ်ပါ။ L, H, A, N ကို သုံးပါ။` ဟု ပေးသည်။
- ဗလာ height သို့မဟုတ် depth သည် 0 ဖြစ်သည်။

## Operators

| ရေးသည် | အဓိပ္ပာယ် |
|---|---|
| `+` | ပေါင်းရန် |
| `-` သို့မဟုတ် `−` | နုတ်ရန်၊ သို့မဟုတ် အနုတ်တန်ဖိုး |
| `*` သို့မဟုတ် `×` | မြှောက်ရန် |
| `/` သို့မဟုတ် `÷` | စားရန် |
| `( )` | အုပ်စုဖွဲ့ရန် |

မြှောက်ခြင်းနှင့် စားခြင်းကို ပေါင်းခြင်းနှင့် နုတ်ခြင်းထက် အရင်လုပ်သည်: `L * 2 + 4` သည် (L × 2) + 4 ဖြစ်သည်။ သံသယရှိလျှင် ကွင်းများ သုံးပါ။

ဒဿမပါသော ကိန်းများ (`1.333`, `.5`) နှင့် exponents (`1e3` = 1000) ရသည်။ Space များကို လျစ်လျူရှုသည်။

## Functions

| Function | ရလဒ် | ဥပမာ |
|---|---|---|
| `ceil(x)` | ကိန်းပြည့်သို့ အထက်သို့ ဝန်း | `ceil(67.5)` = 68 |
| `floor(x)` | ကိန်းပြည့်သို့ အောက်သို့ ဖြတ် | `floor(67.5)` = 67 |
| `round(x)` | အနီးဆုံး ကိန်းပြည့်သို့; ထက်ဝက်ကို သုညမှ ဝေးရာသို့ | `round(2.5)` = 3 |
| `round(x, d)` | ဒဿမ d နေရာသို့ (0 မှ 10) | `round(3.14159, 2)` = 3.14 |
| `min(a, b, …)` | အသေးဆုံး တန်ဖိုး | `min(N, 10)` |
| `max(a, b, …)` | အကြီးဆုံး တန်ဖိုး | `max(1, ceil(N / 12))` |
| `abs(x)` | အမှတ်လက္ခဏာ မပါသော တန်ဖိုး | `abs(-3)` = 3 |

`ceil` နှင့် `floor` သည် computer rounding noise အနည်းငယ်ကို လျစ်လျူရှုသည်၊ ထို့ကြောင့် တိကျစွာ 1 ဖြစ်သင့်သော တန်ဖိုးကို 2 သို့ ဘယ်တော့မှ မတက်ပါ။

## Errors

ဖတ်၍ မရ သို့မဟုတ် တွက်၍ မရသော ပုံသေနည်းသည် field အောက်တွင် error ပြပြီး component သည် စုစုပေါင်းမှ ချန်ထားသည် ({{ui:ပမာဏများ}} header တွင် "Incomplete" ဟု ပြသည်)။ မက်ဆေ့ချ်များ:

| မက်ဆေ့ချ် | ပြင်ရန် |
|---|---|
| ပုံသေနည်း ရိုက်ပါ၊ ဥပမာ L သို့မဟုတ် ceil(L / 1.333) + 1။ | ပုံသေနည်း ဗလာ ဖြစ်နေသည်။ |
| "X" ဤနေရာတွင် တိုင်းတာထားသော တန်ဖိုး မဟုတ်ပါ။ … ကို သုံးပါ။ | အထက်ပါ variables များထဲမှ တစ်ခုကို သုံးပါ။ |
| "X" ဤနေရာတွင် function မဟုတ်ပါ။ ceil, floor, round, min, max, abs ကို သုံးပါ။ | ထို functions များထဲမှ တစ်ခုကို သုံးပါ။ |
| ပုံသေနည်းတွင် "#" ခွင့်မပြုပါ။ | ထို အက္ခရာကို ဖယ်ပါ (unit, `%`, `$` နှင့် `=` ခွင့်မပြုပါ)။ |
| ")" ပျောက်နေသည်။ / "(" မပါဘဲ ")" ရှိနေသည်။ | ကွင်းများကို မျှအောင် ပြင်ပါ။ |
| ")" မတိုင်မီ တန်ဖိုး ပျောက်နေသည်။ | ဥပမာ `max(1, )` ကဲ့သို့ ဖြစ်လျှင် တန်ဖိုး ဖြည့်ပါ။ |
| ပုံသေနည်း အစောကြီး ပြီးနေသည်။ | ဥပမာ `L *` ကဲ့သို့ ဖြစ်လျှင် ပြီးအောင် ရေးပါ။ |
| မမျှော်လင့်သော "…"။ Operator ပျောက်နေသလား? | ဥပမာ `2L` ကဲ့သို့ တန်ဖိုးနှစ်ခု ကပ်နေလျှင် `2 * L` ဟု ရေးပါ။ |
| ceil() က တန်ဖိုး 1 ခု ယူသည်။ | Function သို့ မှန်ကန်သော တန်ဖိုး အရေအတွက် ပေးပါ။ |
| round(x, digits) သည် 0 မှ 10 အထိ ကိန်းပြည့် ဒဿမနေရာ လိုသည်။ | ကိန်းပြည့် ဒဿမနေရာ အရေအတွက် သုံးပါ။ |
| ပုံသေနည်းသည် သုည ဖြင့် စားနေသည်။ | များသောအားဖြင့် H သည် 0 ဖြစ်နေသည်; item ၏ အမြင့် သို့မဟုတ် အနက် သတ်မှတ်ပါ။ |
| ပုံသေနည်းက ဂဏန်း မပေးပါ။ | ရလဒ် ကြီးလွန်း၍ ဂဏန်း မဖြစ်နိုင်ပါ။ |
| ထို ပုံသေနည်း ရှည်လွန်းသည် (အများဆုံး 500 အက္ခရာ)။ | တိုအောင် ပြင်ပါ။ |

## Design ကြောင့် ဘေးကင်းခြင်း

ပုံသေနည်းသည် အထက်ပါ variables နှင့် functions များဖြင့် သင်္ချာတွက်ချက်ရုံသာ လုပ်နိုင်သည်။ Code run ခြင်း သို့မဟုတ် အခြားတစ်ခုခု ဖတ်ခြင်း မလုပ်နိုင်သဖြင့် တစ်စုံတစ်ယောက် ပို့သော project file ထဲရှိ ပုံသေနည်းသည် အန္တရာယ်မရှိပါ။
